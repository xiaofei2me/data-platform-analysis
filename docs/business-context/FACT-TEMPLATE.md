# 业务事实收集模板

每条事实单独填写。未由业务责任方确认的内容不得标记为已确认，也不得仅凭表名、字段名、SQL 或规则推断填写企业业务定义。

## 事实记录

| 字段 | 填写内容 |
| --- | --- |
| 事实 ID | 稳定且唯一的标识 |
| 业务域 | 业务责任方认可的业务域；未确认时写“待确认” |
| 业务对象或过程 | 对象 / 过程名称及类型 |
| 正式业务定义 | 责任方确认的定义原文或经确认的准确摘要 |
| 适用范围 | 组织、产品、渠道、地区、时间范围等适用边界 |
| 关键表、字段和标识 | 表身份、字段名、业务标识及其证据位置 |
| 业务粒度 | 一行或一条记录代表的业务实体 / 事件 |
| 指标口径与排除条件 | 公式、单位、时点、去重口径、纳入 / 排除规则 |
| 业务例外 | 已知例外及其适用条件；没有经确认的例外时写“未确认” |
| 事实来源 | 文档、制度、系统说明或访谈记录的链接 / 引用及日期 |
| 确认人或责任团队 | 负责确认该事实的人员角色或团队 |
| 确认状态 | `draft` / `pending_confirmation` / `confirmed` / `rejected` |
| 与现有机器候选的冲突 | 候选 ID、冲突描述与处理结论；无冲突也需注明已核对 |
| 生效日期或版本 | 生效起止日期、业务版本或规则版本 |

## 证据分类

每项陈述都应标注以下一种类别，不能把机器观察或推导写成已确认业务事实：

- **已确认业务事实**：有可追溯来源，并由业务责任方确认。
- **技术观察事实**：从当前 Snapshot / Inventory / Evidence 直接观察得到，只说明技术元数据或 SQL 行为。
- **规则推导候选**：由当前配置规则或确定性算法推导，仍是候选结果。
- **尚待业务确认的假设**：待验证的问题，不作为 Understanding 的事实输入。

## 记录

复制以上“事实记录”表格填写；没有信息的字段写“待确认”或“未提供”，不要猜测。
